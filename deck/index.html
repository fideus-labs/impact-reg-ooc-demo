The MRI is the measurement one can make on a whole brain; the XPCT is what the tissue really holds, down to axons and cells. Bring the MRI map into XPCT space, and any MRI voxel can be read against the microstructure under it. The map is registered and refined down the pyramid, with the fixed volume never held in memory. Four stages: a global affine, a coarse deformable, the same deformable in tiles one level down, the same tiles on a window of level 0. A fifth stage places the hemisphere’s 4.3 µm scan on the overview the same way.

The mechanism one patch in, one patch out

Registration runs like a deep model

The engine never sees the volume. It is handed one patch of the fixed image and one of the moving image, and returns one patch of displacement. Each patch is read from the store as one region, plus its halo. The displacement patches are blended on their overlaps by a partition of unity, and the assembled field is written slab by slab. Neither end is ever whole in memory: the card holds one patch.

A tile whose fixed mask is empty is not registered: it gets a zero field. Tiles are read, registered and written in the order of the first axis, so the result streams to disk as the run advances.

The component axis is typed displacement, and the store declares a displacements transformation from physical space to physical space. A reader that follows RFC-5 knows the three channels are a vector field in millimetres, in the output axes’ order, and applies it.

What you change three slots, one command

The model, the loss, the patching

model
elastix   FireANTs   ConvexAdam
Same two inputs, same two outputs. Name a preset and the engine changes under it.
loss
intensity   MIND   TotalSegmentator   SAM
Grey levels, or the feature maps a pretrained network computes from each patch. Mutual information here.
patching
patch_size   overlap   patch_combine
What fits the engine to the card, how much neighbouring tiles share, and how their fields are blended. Three lines: the whole difference between a run that must hold the volume and one that never does.
# the level-3 run: 125 tiles of 256³ over a 947 × 947 × 1065 store
impact-reg-konfai register Generic_Rigid_BSpline \
  -f pair3/Fixed.ome.zarr -m pair3/Moving.ome.zarr \
  --fixed-mask pair3/FixedMask.ome.zarr --moving-mask pair3/MovingMask.ome.zarr \
  -o out/linc_tiled3_bend100 --gpu 0 \
  --set "…RegistrationNet.parameter_maps=[Parameters_BSpline.txt]" \
  --set "…RegistrationNet.final_grid_spacing=2.0" \
  --set "…RegistrationNet.max_iterations=200" \
  --set "…RegistrationNet.spatial_samples=4096" \
  --set '…RegistrationNet.parameter_overrides=[Metric="AdvancedMattesMutualInformation"
         "TransformBendingEnergyPenalty", Metric0Weight=1.0, Metric1Weight=100, …]' \
  --set "Predictor.Dataset.Patch.patch_size=[256, 256, 256]" \
  --set "Predictor.Dataset.Patch.overlap=12%" \
  --set "…DisplacementField.OutputDataset.patch_combine=Cosinus"

The preset names the model and the loss; everything else is a --set line. The same command runs at every level of the pyramid. Only the tile count changes.

Level 4 321 µm · the whole hemisphere, in memory

A global affine, then a coarse deformable, on 0.22 GiB

Level 4 is 474 × 474 × 533 voxels, 0.22 GiB. It fits, so the first two stages run on the whole hemisphere with no tiles, and level 0 is never touched. Stage 1 finds a global affine by mutual information. Stage 2 is the coarse deformable, an elastix B-spline with 3 mm control points, 600 iterations, 8192 samples, masked to the tissue and held by a bending penalty: 2 min 06 s.

Measured on the images, the MRI map’s residual shift in 20 mm windows falls from about 1 mm after the affine to zero after the deformable, in all three planes. The map’s own voxel is 0.4 mm: this is the scale at which its placement can be judged.

Stage 5 zoom 1 at 4.257 µm on the overview at 20.07 µm · X-ray against X-ray

The 4.3 µm scan, placed on the overview to within one 20 µm voxel

The same hemisphere was scanned again at 4.257 µm: zoom 1, 602 GiB. The dataset places it on the overview with one affine set by hand. From there: a rigid correction at 80 µm, 17 s; the pair at 40 µm over the zoom’s whole field of view, 3.5 GiB an image; then the tiled command, 294 tiles of 256³, 35 min.

The check runs at 20 µm, twice as fine as the tiles: level 0 of the overview against level 2 of the zoom, in eight windows of 4 mm. The residual shift is the peak of their cross-correlation on the overview’s grid, so under 0.02 mm is within one of its voxels. The gold lines tell the same story: 19 % of the zoom’s edges fall within one 20 µm voxel of the overview’s by hand, 87 % after the tiles. Most of that field is a scale the hand placement lacked, 0.8 to 1.8 % along the axes: between two scans of the same tissue there is little to deform, and the deformable also takes what an affine would. Going down the ladder changes the number of tiles and the wall clock. It does not change the command, and it does not change the memory. One 24 GB card, one workstation.

Run it three ways in

Command line, Python, or 3D Slicer

# install: the CLI, the OME-Zarr reader, the IMPACT metric
pip install impact-reg-konfai "konfai[omezarr,monitoring,s3]" itk-impact

# the tiled run, whatever the level
impact-reg-konfai register Generic_Rigid_BSpline \
    -f Fixed.ome.zarr -m Moving.ome.zarr -o ./out --gpu 0 \
    --fixed-mask FixedMask.ome.zarr --moving-mask MovingMask.ome.zarr \
    --set "Predictor.Dataset.Patch.patch_size=[256, 256, 256]" \
    --set "Predictor.Dataset.Patch.overlap=128" \
    --set "…DisplacementField.OutputDataset.patch_combine=Cosinus"

# another engine, or another loss: one name
impact-reg-konfai register FireANTs_SyN …          # GPU SyN; pip install fireants
impact-reg-konfai register ConvexAdam_Composite …  # coupled convex + Adam
impact-reg-konfai register MR_CT_TS …              # elastix on TotalSegmentator features

# from Python: the same call, the --set lines as config_overrides
from impact_reg_konfai.impact_reg import ImpactRegKonfAIApp
ImpactRegKonfAIApp().register(
    ["Generic_Rigid_BSpline"], [Path("Fixed.ome.zarr")], [Path("Moving.ome.zarr")],
    fixed_masks=[Path("FixedMask.ome.zarr")], moving_masks=[Path("MovingMask.ome.zarr")],
    output=Path("out"), gpu=[0],
    config_overrides=["Predictor.Dataset.Patch.patch_size=[256, 256, 256]",
                      "Predictor.Dataset.Patch.overlap=128"])

Presets and feature models are fetched on first use. A GPU is not required, only faster.
